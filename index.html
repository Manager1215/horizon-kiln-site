Kiln

Java mods in Horizon

Kiln runs Java (Fabric) mods in Horizon, the Rust rewrite of Minecraft: Java Edition 26.3, the way Proton runs Windows games on Linux: the mod's code runs as it is, and its calls to Minecraft's classes and the Fabric API become calls into Horizon.

Latest public release 0.4.1, 9 November 2026. Every release proof of 0.4.0 ran in the game on Linux.

How it works

You need the Horizon launcher with 26.3 prepared, and Java 25. The steps are in INSTALL.md in the repository, where they stay current.

Kiln is a native Horizon mod. It starts Java beside the game, not inside it, runs each mod's entrypoints from its fabric.mod.json, gives mods the game's state every tick, and draws what they draw on the HUD.

  1. 1

    Install Kiln once

    The Horizon launcher builds Kiln into the game, after you agree to it. Native Horizon mods run without a sandbox, so read the code first.

  2. 2

    Drop in your mods

    Put .jar mods into <game folder>/kiln/mods/.

  3. 3

    Play

    Kiln runs each mod's entrypoints, gives it the game's state every tick, and draws what it draws on the HUD.

Kiln + Horizon's mod browser

Partly is the mod browser's mark for mods whose features need Java code: the launcher imported the data, the code did not come along. With Kiln installed, that code runs too, as far as Kiln covers today.

Horizon brings the data, Kiln the code. Kiln and Horizon's mod browser work together, each taking one half of a Java mod.

Data: Horizon

Horizon's launcher carries a Java mod's data into a Horizon content mod.

Blocks, items, recipes, structures.

Code: Kiln

Mods whose features need Java code are marked Partly in the mod browser. Kiln runs that code, beside the game.

Entrypoints, the game's state every tick, HUD drawing; on the single-player server, items, events, saved data, loot and blocks.

FAQ

The short answers. The code and INSTALL.md in the repository have the long ones.

Is it safe?

Native Horizon mods run without a sandbox, with your rights, and Kiln is one of them. The launcher builds it only after you explicitly agree. Kiln is open source: read the code first. The Java mods it runs also run with your rights, as any Java mod does.

Which mods work?

Fabric mods for 26.3 that use what Kiln already covers. The list of mods grows with each release and says how far each one has been checked. There is no Mixin support yet; it is on the roadmap for 0.5.

What is Kiln’s test stand?

Before anyone tries a mod in the game, Kiln runs it automatically on a test stand: the mod’s own code, in a real Java, the way Kiln runs it in the game, with a scripted minute of play in place of Horizon (a new world, a key press, a trip to the Nether, a pause). That shows the mod starts and nothing breaks. It doesn’t show that each of its features appears in the game: a feature may need something the script doesn’t have. So a mod that passes is “Should work”; only a mod someone tried in the game is “Works”.

What are the development builds?

Kiln is developed in the open, and most days bring mods to life that the last release does not run yet. The catalogue shows two layers for each mod: what the latest release does, and what the current development build does, named by its date and commit. The release layer is the default; the switch on the mods page counts the development build instead. A development build is the main branch as it is that day, not a release: it can break, and it comes with no promise. Nightly builds of it are planned; until they exist, a development build means building Kiln from the source at that commit.

Can a mod break my game?

Kiln runs Java mods in a Java process of their own, beside the game. A mod that fails loses its own feature, and Kiln says so; a mod that hangs makes Kiln stop Java, and Horizon goes on. A mod that keeps data in your world, a machine for example, writes it into your save, so back up the worlds you care about before you try one.

Does Kiln change or decompile a mod?

No. A mod's jar runs as it is, in a Java process beside the game: nothing in it is decompiled, translated or patched. What a mod calls in Minecraft and the Fabric API is answered by Kiln's own stand-ins, which share only the names of those classes and methods; Kiln's repository holds no Minecraft code, assets or files. A mod's own license applies as it does with Fabric, and Kiln redistributes no mods.

Does it run on Windows or Linux?

Linux: 0.4.0 was tested in the game on Linux (Arch), every release proof and 160 mods. macOS: 0.3.0 was tested in the game on Apple Silicon. Windows: 0.2.0 was tested on Windows 11 from a fresh install; 0.3.0 and 0.4.0 not yet.

Accounts and reports

Each mod’s page collects reports from players: whether the mod ran for you in Horizon (it works, partly, or it doesn’t), with which Kiln build and which version of the mod, and what you saw, in up to 400 characters. Reports come from accounts and show at once, with the account’s name and the date. There is one per mod and build, and you can change or delete yours at any time; reports by the Kiln team carry a mark. To write one, make an account with an e-mail address and a password. Deleting the account, on its page, deletes its reports with it; Your data says what is kept and for how long.

Is it official?

No. Kiln is not affiliated with Horizon, Mojang or Microsoft. It is an independent open-source project.
